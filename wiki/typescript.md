# TypeScript

**Summary**: TypeScript configuration, key type exports, and caveats learned during the JS→TS migration.

**Sources**: tsconfig.json, infra/controller.ts, models/authorization.ts, infra/database.ts

**Last updated**: 2026-06-08

---

The codebase was migrated from JavaScript to TypeScript in PR #10. All source files are `.ts`/`.tsx`. Migration files in `infra/migrations/` remain as `.js` (see [[migrations]]).

## tsconfig.json decisions

| Option               | Value                                   | Why                                                                                        |
| -------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------ |
| `strict`             | `true`                                  | Full strict mode — `noImplicitAny`, `strictNullChecks`, etc.                               |
| `moduleResolution`   | `"bundler"`                             | Correct for Next.js 15 + SWC; resolves extensionless imports to `.ts`                      |
| `allowJs`            | `false`                                 | Any unconverted `.js` file fails `tsc`, enforcing full migration                           |
| `baseUrl`            | `"."`                                   | Enables bare imports: `import from "infra/database"` without relative paths                |
| `ignoreDeprecations` | `"6.0"`                                 | Suppresses TypeScript 6 deprecation warning for `baseUrl`                                  |
| `types`              | `["jest","node"]`                       | Required with `moduleResolution: "bundler"` — Jest globals are NOT auto-included otherwise |
| `exclude`            | `["infra/migrations", "infra/scripts"]` | CJS files not compiled by tsc                                                              |

## Key type exports

### `models/authorization.ts`

```ts
export type Feature = "create:user" | "read:user" | ... ; // all 14 features
export interface AuthUser { features: string[]; id?: string; }
```

### `models/user.ts`

```ts
export interface UserRow {
  id: string;
  username: string;
  email: string;
  password: string;
  features: Feature[];
  created_at: Date;
  updated_at: Date;
}
export interface UserCreateInput {
  username: string;
  email: string;
  password: string;
  features?: Feature[];
}
```

### `infra/controller.ts`

```ts
export interface AnonymousUser {
  features: Feature[];
}
export type ContextUser = UserRow | AnonymousUser;
export interface AppApiRequest extends NextApiRequest {
  context: { user: ContextUser };
}
```

All 9 API routes are typed as `createRouter<AppApiRequest, NextApiResponse>()`.

### `infra/database.ts`

```ts
async function query<T extends QueryResultRow = QueryResultRow>(
  queryObject: string | QueryConfig,
): Promise<QueryResult<T>>;
```

Every model passes its row interface as the generic: `database.query<UserRow>(...)`.

## ESLint: files excluded from TypeScript rules

`@typescript-eslint` rules are applied to all files by default. Add to `ignorePatterns` in `.eslintrc.json` to avoid false positives on CJS files:

```json
"ignorePatterns": [
  "next-env.d.ts",
  "jest.config.js",
  "commitlint.config.js",
  "infra/migrations/",
  "infra/scripts/"
]
```

`next-env.d.ts` is auto-generated by Next.js and would otherwise fail `@typescript-eslint/triple-slash-reference`.

## Caveats

- **`next-connect` `onError`** takes 3 params `(err, req, res)`, not 4. Passing a 4th `next` parameter causes a type error in all route files.
- **`request.cookies[key]`** is `string | undefined`. Use non-null assertion (`!`) after an explicit truthiness guard.
- **`Date - Date` arithmetic** is not allowed in strict mode. Use `.getTime()` on both operands.
- **`setCookieParser` with fetch `Response`**: the library types expect `IncomingMessage | string | string[]`. Use `response.headers.getSetCookie()` (Node 20+) instead.
- **`node-pg-migrate` runner** returns `RunMigration[]`, but `RunMigration` is not exported from the package index. Drop explicit return type annotations on migrator functions and let TypeScript infer.
